# Guide de migration d’E4X

L’extension E4X pour la prise en charge native de XML dans JavaScript est progressivement abandonnée par Mozilla. Adobe Campaign a fortement utilisé cette extension et se prépare donc à migrer vers une solution alternative.

L’objectif de ce guide est de vous aider à migrer les configurations existantes ou à développer de nouvelles configurations en décrivant les solutions de remplacement.

L’ancien et le nouveau système coexistent. La version actuelle d’Adobe Campaign est toujours compatible avec E4X, mais les nouvelles configurations ne doivent pas être développées avec l’extension E4X.

Rappel : E4X ajoute un type de fichier XML JavaScript qui peut être créé directement à partir du programme source :

```text
var doc = <xml> ... </xml>
```

ou à partir d’une chaîne :

```text
var doc = new XML ("<xml>...</xml>")
```

Il peut ensuite être manipulé avec une API spécifique :

```text
element.@id element.where
```

## Type XML

Le type « xml » natif est remplacé par une API DOM. Il s&#39;agit des types [DOMDocument](c-domdocument.md) , [DOMElement](c-domelement.md) , [DOMNode](c-domnode.md), ... Voici l&#39;équivalent des opérations les plus courantes :

> **E4X:**
>
> ```javascript
> anElement.@id
> ```
>
> **DOM:**
>
> ```javascript
> anElement.$id
> ```
>
> **E4X:**
>
> ```javascript
> anElement.@["recipient-id"]
> ```
>
> **DOM:**
>
> ```javascript
> anElement["$recipient-id"]
> ```
>
> **E4X:**
>
> ```javascript
> anElement.childElement
> ```
>
> **DOM:**
>
> ```javascript
> anElement.getElements("childElement")
> ```
>
> ou
>
> ```javascript
> anElement.getFirstElement("childElement")
> ```

Les documents XML d&#39;un JavaScript doivent être remplacés. Lorsque ce document doit être utilisé pour une fonction native ou un appel SOAP transmettant un document XML en paramètre, vous pouvez transmettre directement un JXON. Celle-ci sera automatiquement transformée en document XML (DOMDocument). Dans le cas contraire, vous pouvez toujours transmettre via un objet JXON, mais une conversion explicite à l’aide de la fonction [DOMDocument.fromJXON](m-domdocument-fromjxon.md) est requise.

```javascript
var doc = DOMDocument.fromJXON({queryDef: 
{schema: "xtk:workflow", operation: "select",
  select: { node: {expr: "@internalName"} } 
}
})
```

Exemple d&#39;équivalence entre une syntaxe XML et JSON :

> **E4X:**
>
> ```xml
>                             <queryDef schema="nms:delivery" operation="get">
>     <select>
>         <node expr="@created"/>
>         <node expr="@lastModified"/>
>     </select>
>     <where>
>         <condition expr="@id=123456"/>
>     </where>
> </queryDef>
> ```
>
> **JXON:**
>
> ```javascript
>                             {queryDef: {schema: "nms:delivery", operation: "get", 
>     select: {
>         node: [
>             {expr: "@created"}, 
>             {expr: "@lastModified"}]
>         }, 
>     where: {
>         condition: {expr: "@id=123456"}
>     }
> }}
> ```

Pour plus d&#39;informations sur la syntaxe JSON, consultez la page Utilisation de XML .

## Appels SOAP

Ces méthodes SOAP doivent exécuter les propriétés d&#39;objet NLWS. L’identifiant JavaScript du schéma est créé à partir de l’espace de noms et du nom commençant par une majuscule. Par exemple, le schéma nms:delivery aura nmsDelivery comme identifiant JS.

> **Ancien :**
>
> ```javascript
> nms.delivery.Play(deliveryId);
> ```
>
> **Nouveau :**
>
> ```javascript
> NLWS.nmsDelivery.Play(deliveryId);
> ```

## Méthodes de SOAP JavaScript

Pour recevoir un document XML dont les paramètres sont au format DOM plutôt qu&#39;au format E4X, l&#39;attribut dom=« true » doit être ajouté dans le schéma.

## Chaînes multilignes

L&#39;utilisation de XML pour construire des chaînes multilignes doit être remplacée par une concaténation de chaînes en oubliant d&#39;ajouter la fin de la ligne \\n.

> **Ancien :**
>
> ```xml
> <str>line 1
> line 2
> line 3
> </str>.toString()
> ```
>
> **Nouveau :**
>
> ```javascript
> "line 1\n" +
> "line 2\n" +
> "line 3\n"
> ```

## Gestion de contenu

Il est nécessaire d’activer l’option DOM dans le modèle de publication ou à partir du modèle JavaScript lors de la prévisualisation. Pour une transformation XSL avec pré-traitement JavaScript, vous devez également activer l&#39;option DOM (fenêtre d&#39;agrégation).
